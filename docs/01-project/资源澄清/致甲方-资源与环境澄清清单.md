# 资源与环境澄清清单

**项目**：AI 智能体平台部署
**用途**：确定部署方案与实施工作量。以下 23 项为技术与实施必需信息，请协助确认。
**日期**：2026-09-18

标注 ★ 的 6 项为阻塞项——未确认无法确定部署方案。

---

## 一、硬件资源

- [ ] **★H1** 华为服务器的具体型号？是 TaiShan 200（鲲鹏 ARM 架构）还是 2288H（Intel x86 架构）？
      *说明：架构不同，软件包需要重新构建，工作量不同。*
- [ ] **★H2** 昇腾卡的型号与数量？Atlas 300I Duo / 300V Pro / 800I A2（910B）？单卡显存多大？
      *说明：决定可运行的模型规模与并发能力。*
- [ ] **★H3** 联想服务器的型号、CPU 核数、内存、当前可用磁盘空间？
      *说明：平台需 ≥4 核 8G、100GB 磁盘；若该服务器已有其他系统在用，需确认剩余资源。*
- [ ] H4 是否有共享存储 / NAS / 备份一体机可复用？
- [ ] H5 机房是否有独立机柜空间与供电余量？（昇腾卡功耗较高，单卡 300W 以上）

## 二、操作系统与平台

- [ ] **★S1** 两台服务器各自的操作系统与版本？（openEuler 20.03 / 22.03、麒麟 V10 SP3、统信 UOS、CentOS 7 / 8、Ubuntu 22.04）
      *说明：CentOS 7 内核较旧，可能无法安装新版加速卡驱动。*
- [ ] **★S2** 服务器上的容器引擎是什么？Docker（版本号？）、containerd、还是 iSulad？是否已部署 K8s？
      *说明：若为 iSulad，现有容器编排方案需改造，工作量增加。*
- [ ] **★S3** 服务器是裸机安装，还是运行在虚拟化平台上（华为 FusionCompute / VMware / 深信服）？
- [ ] **★S4** 是否已安装昇腾驱动与 CANN？版本号是多少？由谁安装的？
- [ ] S5 是否已安装 Ascend Docker Runtime？安装需要重启容器引擎，需安排停机窗口。
- [ ] **★S6** 招标文件或院内规范是否强制要求"系统必须运行在国产 CPU 上"？
      *说明：若有强制要求，部署方案需要调整，工作量增加。*

## 三、虚拟化与设备直通（关键）

- [ ] **★V1** 昇腾卡是物理直连给操作系统，还是需要 PCIe 直通给某台虚拟机？
      *说明：若需直通，需在 BIOS 开启相关选项并做专门配置，且部分卡型对虚拟化直通支持有限。这一条会直接影响方案可行性。*
- [ ] **★V2** 虚拟化平台的加速卡直通，是否有已实施的成功案例？能否请华为原厂书面确认支持？
- [ ] V3 联想服务器是否也运行在虚拟机中？（平台本身跑在虚拟机里没有问题，仅需确认）

## 四、网络与安全合规

- [ ] **★N1** 两台服务器是否在同一网段互通？中间是否有防火墙策略需要报备开通端口？
      *说明：平台需访问推理服务的 HTTP 端点。跨网段变更审批可能需 1–2 周，建议尽早发起。*
- [ ] **★N2** 院内网是否可以访问公网？是否有出口白名单机制？
- [ ] **★N3** 需要接入哪些即时通讯通道（企业微信 / 钉钉 / 飞书）？
      *说明：这些通道需要访问公网。若院内网严格隔离，则通道功能不可用，只能使用网页端。此项需提前确认，避免影响验收。*
- [ ] N4 系统等保等级是几级？是否有安全加固基线要求（如禁止 root 运行、日志留存期限）？
- [ ] N5 是否需要接入堡垒机 / 准入系统 / 日志审计平台？
- [ ] N6 使用终端是什么？院内电脑的浏览器版本？是否有国产操作系统终端？

## 五、模型与推理服务

- [ ] **★M1** 计划运行哪个模型？DeepSeek-V4-Flash 还是其他？模型文件由哪一方提供？
- [ ] **★M2** 推理服务的部署（MindIE / vLLM-Ascend）是否包含在本项目交付范围内？还是由华为原厂或其他集成商负责？
      *说明：这一项直接决定项目范围与报价，需要明确。*
- [ ] M3 模型的使用许可由哪一方负责？医院是否已有采购凭证？
- [ ] M4 是否允许调用外部云端大模型接口作为补充？（涉及数据出院合规）

## 六、业务与规模

- [ ] B1 预计使用人数与并发量？峰值时段预计多少人同时使用？
- [ ] B2 需要哪些具体能力？（文档处理 / 网页自动化 / 定时任务 / 知识库检索等）
- [ ] B3 是否需要对接 HIS / EMR / LIS 等院内系统？接口由谁提供、采用什么协议？
      *说明：院内系统接口通常需原厂商配合，周期较长，建议单独立项。*
- [ ] B4 是否涉及患者隐私数据？是否需要脱敏处理？

## 七、运维责任

- [ ] O1 加速卡驱动 / CANN / 固件的升级与故障处理由哪一方负责？
      *说明：驱动与操作系统内核版本强绑定，内核升级后驱动需重装，属长期维护事项。*
- [ ] O2 服务器硬件维保由哪一方承担？设备是否在保？
- [ ] O3 运维期长度（1 年 / 3 年 / 5 年）？故障响应时限要求？
