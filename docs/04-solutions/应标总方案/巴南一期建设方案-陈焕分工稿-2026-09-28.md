# 陈焕分工稿（合稿用）

## 3.1 总体逻辑架构

整体架构分五层：数据源层、集成与数据层、智能体中台层、应用层、交互层。下层为上层提供支撑，层间通过标准接口解耦，新增应用不改动已有层级。

【架构图占位：五层架构总图】

| 层级 | 组成 | 说明 |
|---|---|---|
| 数据源层 | HIS/EMR（卫宁）、LIS、PACS、超声系统、体检系统、病理系统、互联网医院（金蝶）、县域健共体平台（万达）、病理扫描设备 | 全院业务系统已接入 ESB 集成平台，取数优先复用 ESB 既有接口；万达平台数据接入需经区卫健委协调 |
| 集成与数据层 | ESB 取数适配、数据共享与治理、高质量数据集、数据权限管理 | 详见 3.3（陈小军）与 4.6（桂颖丽） |
| 智能体中台层 | 算力池化调度、模型纳管与版本、提示词/工作流配置、统一服务网关、监控与审计日志 | 一期交付基础管理能力，详见 4.1 |
| 应用层 | 病历生成、病历内涵质控、超声语音报告、体检随访、数据驾驶舱 | 各智能体独立建设、统一挂载中台，详见第 4 章 |
| 交互层 | 医师工作站嵌入页、护士工作站、体检窗口与院内公众号、互联网医院、PC 端 BI 看板 | 医师工作站嵌入需 HIS 侧提供嵌入能力；对外渠道（公众号、互联网医院）须经院内授权流程 |

三点架构说明：

一、中台是唯一模型出口。所有智能体应用统一通过中台调用模型与算力，模型替换升级不改动应用代码。中台内部的分层设计（容器底座、算力池、模型纳管、编排配置、服务网关、数据服务、运维审计七层）在 4.1 展开，此处不展开。

二、数据链路三条进、多条写出。取数链路三条：院内业务数据经 ESB、互联网医院数据经金蝶接口、县域健共体数据经万达平台（待区卫健委协调）。写出链路按模块分设：病历草稿回写卫宁电子病历书写页面（草稿层不落库，医生保存才落「未定」库）；超声报告回写超声工作站（由超声软件公司按同一模式改造：草稿层不落库，保存才落「未定」库）；体检随访的患者通知与挂号支付信息经金蝶互联网医院/院内公众号输出（须经院内授权流程）；随访数据只从既有随访系统读取、不回写，随访展示与记录留存于本平台；远程影像/远程病理旧系统的报告回写列于二期；病理数字切片由外购设备推送至现有病理智能体系统。写出链路均依赖原厂商配合改造，属本项目重点交付风险项，详见 8.4。

三、嵌入不替代。各智能体以嵌入方式挂载到现有业务流，不改动业务系统主体架构，不新建独立通道，不干扰现有系统运行。

## 3.2 技术路线

**部署形态**：全栈院内私有化部署，模型推理、语音识别、数据存储全部在院内网完成，不调用任何外部 API。全部组件以容器镜像形态交付，适配院内网无外网环境，镜像、依赖包、模型文件交付前完成离线打包。容器底座采用 Docker（不上 K8s 多节点集群），镜像以离线 tar 包分发。

**算力生态**：国产算力平台（鲲鹏 CPU / 昇腾 NPU）。需要明确披露：华为生态与英伟达生态存在差异，推理框架（MindIE / vLLM-Ascend）、算子与模型适配方案需与华为公司确认后锁定，本项目预留适配与调优工期。依据显存核算结论，200GB 级昇腾卡可承载 DeepSeek-V4 级模型推理，病历生成与内涵质控的 7B–14B 级 INT8 量化模型负载有充足余量。

**信创要求**：CPU 架构（鲲鹏 ARM 或 x86）与操作系统（openEuler / 麒麟 / 统信）以信息科书面确认结论为准，软件包按确认结果构建。

**大模型选型策略**：本地私有化部署模型为主。如需混合调用外部云端模型接口作为补充，涉及数据出院合规，须单独走院内审批，一期默认不启用。

**语音识别**：院内本地推理，支持国产算力，音频不出院区。

## 4.1 模块一：智能体中台（基础管理能力版）

### 4.1.1 建设定位与一期边界

一期只交付基础管理能力——算力池化调度、模型统一纳管与启停、基础监控与日志、账号权限；不交付招标文件「统一技术底座」的全量能力（低代码编排全栈、灰度发布与回滚体系、服务网关全功能等）。该边界依据 0922 信息科现场会确认口径：一期纳入算力池化、模型纳管等基本管理功能，其余能力按分期路线图在二期扩展。

| 层 | 一期交付 | 二期扩展 |
|---|---|---|
| L1 容器底座 | Docker 容器化、离线镜像包、基础日志 | K8s 多节点高可用、私有镜像仓库、统一身份认证对接 |
| L2 算力池 | 资源池台账、任务队列、基础阈值告警 | 显存切分、动态弹性调度、熔断策略矩阵 |
| L3 模型纳管 | 大模型注册/版本/启停/监控/台账；《模型接入标准化规范》；影像/病理模型接口预留 | 影像 AI、病理 AI 模型逐厂商适配 |
| L4 开发编排 | 提示词模板管理、业务规则配置、简单工作流（现成编排引擎配置界面） | 可视化拖拽编辑器、多智能体协同编排、灰度发布、独立调试环境 |
| L5 服务网关 | 成熟网关开箱配置（鉴权、限流、熔断）、基础访问日志 | 流量统计报表、全链路调用日志、统一服务目录 |
| L6 数据服务 | ESB 取数适配层、数据访问审计日志 | 数据集全流程服务、字段级行级权限引擎、脱敏引擎 |
| L7 运维审计 | 审计日志（不可篡改、留存期满足等保要求）、基础指标告警 | 监控大屏、驾驶舱联动 |

### 4.1.2 业务流程设计

【流程图占位：模型生命周期 + 算力分配】

模型生命周期：模型注册（登记名称、类型、版本、来源、责任科室）→ 评估（调用验证、性能初测）→ 上线（纳入统一推理服务、分配算力额度）→ 调用监控（时延、成功率、资源占用）→ 下线（停用并释放算力，台账保留记录）。

算力资源流程：智能体应用提交资源申请（用途、峰值预估、优先级）→ 中台按池化台账分配额度 → 运行期按队列与优先级调度（临床实时任务优先，批量任务排队）→ 变更或回收留痕。

### 4.1.3 技术方案

- 容器化底座：Docker 容器化部署，离线 tar 包分发，部署、升级、回滚均为镜像级操作，不依赖互联网。
- GPU/CPU 资源池化与任务队列：现有服务器算力统一纳管为资源池，屏蔽物理机差异；任务按优先级排队调度，超时与失败任务自动终止并告警。
- 模型注册表与版本管理：统一模型台账，支持多版本并存、版本切换、一键回退，变更全程留痕。
- 统一推理服务封装与调用日志：上层应用统一经中台调用模型，调用记录含调用方、时间、参数摘要、结果状态、耗时。
- 与华为算力平台对接方式：待华为确认（昇腾驱动/CANN 版本、推理框架选型、设备直通方案），接口边界预留。

### 4.1.4 功能清单

| 功能点 | 功能说明 | 优先级 |
|---|---|---|
| 算力池化管理 | GPU/CPU 资源统一纳管、台账、额度分配 | P0 |
| 模型纳管 | 模型注册、台账、版本、启停 | P0 |
| 模型版本管理 | 多版本并存、切换、回退、留痕 | P0 |
| 调用统计与监控 | 调用量、时延、成功率、资源占用报表与告警 | P0 |
| 权限与审计 | 账号角色分级、全操作审计日志（不可篡改） | P0 |
| API 网关基础能力 | 鉴权、限流、熔断、基础访问日志 | P0 |
| 提示词与规则配置 | 提示词模板、业务规则、简单工作流配置 | P1 |
| 模型接入标准化规范 | 接口协议、数据格式、鉴权、健康检查、错误码文档 | P1 |

### 4.1.5 与院内系统接口

| 源系统 | 接口方式 | 数据内容 | 责任方 |
|---|---|---|---|
| 院内 ESB 集成平台 | ESB 既有接口复用 | 各智能体取数 | 医院信息科协调 |

| 华为算力平台 | 待定（待华为确认） | 算力调度、监控数据 | 华为 |

### 4.1.6 功能实现结果

中台管理界面可演示；各智能体统一从中台取模型与算力；可查看模型调用量与资源占用报表；模型注册、上线、停用全程留痕；审计日志可追溯且不可篡改。

### 4.1.7 验收要点

模型纳管数量（一期纳入全部上线模型）；算力调度生效证据（分配、排队、回收记录）；监控报表完整；审计日志可追溯；《模型接入标准化规范》交付。

## 4.2 模块二：AI 病历生成智能体

### 4.2.1 建设定位与一期边界

只做草稿层生成，不直接落库。覆盖门诊、住院指定试点科室。牙科住院等带牙槽图片的特殊病历，实施阶段再定方案。

边界外声明（不接受配置项开关）：不做诊断与治疗建议生成，触发即停止文书流程；不做跨患者数据训练，院内数据用于训练需另行立项授权；不做自动归档、自动签名，系统最高状态为「可复核草稿」。

### 4.2.2 业务流程设计

【流程图占位】

智能体生成 → 医生审核修改 → 医生逐项确认 → 医生个人签名 → 保存提交。生成内容停留在草稿层，与病历库隔离；医生执行保存动作时才触发落「未定」库（对卫宁改造量最小的路径）。AI 生成内容医生必须审阅后再签名，系统不触发任何归档与签名动作。

### 4.2.3 技术方案

**多源数据聚合**：经 ESB 取 HIS、LIS、PACS、超声、手术记录等多源数据，字段白名单按需读取，禁止批量同步全量数据；患者范围严格限定当前患者 + 当前就诊；每条数据附「已核实/初步/未核实」状态。

**事实账本与证据分级**：每条输入先标注来源与证据等级再进入统一事实账本——A 级（系统已核实记录）可作冲突判定锚；B 级（医师录入）承载查体与判断；C 级（患者陈述）永不升格为查体结果或诊断。无法判定来源默认归 C 级并标记待医师确认。

**零模型区（数值与固定段落不进模型）**：全身体格检查走逐项勾选（正常/异常描述/未查），禁止默认全部正常；生命体征、检验值、剂量、单位走确定性槽位回填，模型输出中不得出现任何数值；个人史/婚育史/家族史走结构化字段；诊断名称引用已确认诊断，不由模型生成。

**受控语言生成**：模型只看到事实账本中已确认的事实；每个句子必须映射至少一个事实编号，无法映射的句子不允许产出；未提及的内容不得改写为「未见异常」「否认」「阴性」；缺口以「待补充」占位呈现。

**独立校验**：校验模块不携带生成过程的上下文（架构级约束，不得自审）。校验类别：无源陈述、事实冲突、诊断强度升级、左右侧一致性、时间线一致性、单位一致性、必填项完整性、否定表述合规。发现任一无源陈述即禁止回写。

**缺口补问**：每轮 3–7 个中性问题，不提供候选答案；最多补问两轮，两轮后仍有关键缺口则停止生成，状态保持「待复核」。

**模板与术语库**：固定骨架 + 可变叙事段 + 槽位定义；科室可视化配置，无需开发介入；变更留版本可回滚，历史病历按生成时模板版本回溯。

### 4.2.4 功能清单

| 功能点 | 功能说明 | 优先级 |
|---|---|---|
| 数据自动聚合 | ESB 多源取数，白名单按需读取，状态标记 | P0 |
| 病历初稿生成 | 入院记录/病程记录/诊疗小结/随访记录初稿 | P0 |
| 必填与选填区分 | 按文书类型必填项清单逐项比对，缺口检出 | P0 |
| 医师确认与签名流程 | 逐项确认（无源句子不可勾选）、医生签名、保存落未定库 | P0 |
| 痕迹留存 | 取数、事实账本、生成稿（句级映射）、修改稿、确认与回写记录全留存 | P0 |
| 模板与术语库管理 | 可视化维护、版本管控、批量导入 | P1 |
| 缺口补问 | 中性问题补问，上限两轮 | P1 |

### 4.2.5 与院内系统接口

| 源系统 | 接口方式 | 数据内容 | 责任方 |
|---|---|---|---|
| ESB 集成平台 | ESB 既有接口 | 取：HIS/LIS/PACS/超声/手术记录 | 医院信息科协调 |
| 卫宁电子病历书写页面 | 反写接口 | 写：病历草稿（草稿层，保存才落未定库） | 卫宁负责改造；需明确接口规范、字段映射与联调计划，医院信息科协调推动 |
| 病历内涵质控模块 | 中台数据接口 | 输出：结构化病历数据、必填项清单、缺口记录 | 我方（与 4.3 耦合） |

### 4.2.6 功能实现结果

医师工作站可调起初稿并一键采纳；单份病历书写时间下降（基线与降幅在试点期实测）；AI 生成与人工修改痕迹完整可溯源；生成内容不出现在病历库，直到医生执行保存；无越权落库。

### 4.2.7 验收要点

试点科室覆盖；采纳率与修改率统计可查；痕迹审计可演示（每句可回溯事实依据）；无源句子拦截率 100%（硬约束）；必填项缺口检出率 100%（硬约束）；取数耗时 ≤ 3s（设计目标，试点期标定）。识别类指标与采纳率基线在试点期以科室真实数据实测后写入验收标准。

## 4.4 模块四：超声语音报告智能体

### 4.4.1 建设定位与一期边界

面向各类型超声检查场景，作为报告辅助工具，不替代医师诊断，报告须医生审核确认后生效。一期试点锚点为阴超单诊室的完整闭环（口述到报告回写），后续按诊室逐个接入。

边界外声明：不做超声图像 AI 识别（属医疗器械监管范畴，需 NMPA 注册证）；不做诊断性结论生成，分级由医生口述、系统只做白名单校验与一致性告警。声音采集器由医院负责落实。

### 4.4.2 业务流程设计

【流程图占位】

医生口述（脚踏/按键控制采集起止）→ 语音识别与降噪 → 内容自动区分报告/非报告 → 测值提取（进待确认池）→ 模板套用与口语规范化 → 结构化报告生成 → 医生逐项确认 → 报告以草稿层状态回写超声工作站（不落库，医生保存时才落「未定」库，改造模式与卫宁病历草稿回写一致），审核签发在院内系统内由医生完成。

### 4.4.3 技术方案

**声学前端**：16kHz/16bit 单声道采样；USB 医用麦克风/领夹麦/网络麦克风接入（型号现场勘察后定）；稳态噪声抑制 ≥ 15dB（设计目标）；回声消除；脚踏开关/热键/语音指令词控制。

**院内语音识别**：本地推理，支持国产算力，音频不出院区；一期整段批处理（检查结束后统一转写），流式增量列二期；超声专科热词表初始 ≥ 3000 条，科室可自行维护；逐片段置信度输出，低置信片段标红待确认、不自动进入报告。

**声源隔离（串患者风险防控）**：同室多机场景下邻位医生口述在语义上就是一份完整规范的报告，语义判别无法区分，必须在声学层解决——近场定向拾音（≤ 30cm）+ 脚踏采集窗口控制 + 麦克风-超声设备-报告会话三方工位绑定，音频无法绑定工位则拒绝进入报告流程。若科室确为一室多机布局，吊装/全向麦方案作废，识别率指标须按多声源环境重新标定。

**测值与槽位抽取**：抽取数值+单位+维度+部位，一律进「待确认池」，经医生确认后由确定性槽位回填，数值不经过语言模型；单位白名单与按部位量级校验（如子宫长径 > 200mm 触发人工复核）。

**模板与分级**：固定骨架（模板引擎）+ 可变描述段（受控生成）；BI-RADS/TI-RADS/LI-RADS/O-RADS 分级走枚举白名单，模型不允许生成白名单外取值；分级与所见描述匹配性校验。

**质控校验**：实时（口述过程即时提示）+ 提交前（全量复核）双模式；校验必填项完整性、测值合理性、左右侧一致性、分级一致性、术语规范性、无源陈述、冲突检测。存在未解决冲突或关键缺口时，报告无法进入「可复核草稿」。

**安全闸门（六道）**：① 音频必须绑定确定工位，否则拒绝进入报告流程；② 数值不进模型，一律经待确认池；③ 左右侧与部位三方不一致即阻断，医生显式裁决；④ 分级走白名单，矛盾即阻断提交；⑤ 生成与校验上下文隔离，不得自审；⑥ 医生逐项确认，无源句子不可勾选，不得笼统确认。

## 4.5 模块五：体检随访智能体

### 4.5.1 建设定位与一期边界

随访只做体检随访——体检与随访合并建设，不重复建设院内随访系统；一期切入病种为宫颈癌筛查（HPV）。筛查前置指引、报告结构化解读、健康宣教的内容一期不在本模块展开，本模块与解读相关的能力共用受检者主索引与风险分层结果。

患者触达边界（硬约束，不接受配置项开关）：解读、提醒内容不直接自动对外推送患者，必须经院内授权流程输出；系统不得自行向患者发送任何消息，越权发送视为严重故障。紧急项「立即推送」指经医护确认后由院内授权通道即时发出，非系统自动发送。

### 4.5.2 业务流程设计

【流程图占位】

体检结果出来 → 智能体后台自动识别并分层（最紧急/可缓）→ 紧急项经医护确认后经院内授权通道推送通知患者（短信/公众号/互联网医院）→ 患者来院随访或就诊 → 推送医生信息、挂号信息与挂号支付入口 → 患者线上支付 → 推送就诊时间 → 到院直接做检查 → 数据归集到门诊，提升体检转化率与收入。

分层结果为「建议分层」，进入待确认池，医护确认后生效；未经确认的分层不生成随访任务、不触发提醒、不计入统计。

### 4.5.3 技术方案

- 复用随访系统既有数据做推荐应用场景，智能体独立建设，不改随访系统。
- 风险分层：确定性规则引擎 + 模型评分。分级依据与档位由院方给定（分级标准是分层与推送的唯一接口，需院方明确）；规则表未覆盖的组合标记「待医师判定」，禁止猜测归并。
- 推送通道：经院内授权的短信/公众号/互联网医院通道；每次推送关联确认记录（确认人、时间、内容版本），支持撤回（限未展示内容）并留痕。
- 推送频率与患者授权管理：频率上限、分层推送策略、退订与授权管理机制，防止推送过频引发投诉。
- 与互联网医院（金蝶）打通挂号与支付：挂号信息、支付入口、就诊时间推送经金蝶侧接口输出，接口边界与联调计划另行确认。
- 数据归集：按患者主索引归并为时间序列，历次检验、影像、病理结果同屏可溯；院外复查结果由医护人工补录「已复查」标记；统计口径统一为「院内可证实完成率」，不声称真实完成率。
