一模块定位与需求溯源

本模块解决一件事：把院内已有的业务数据，转成一份每句有出处、缺口看得见的病历初稿，交给医师修订。系统不写诊断、不下结论、不自动归档。

1.1 招标条款响应总览

招标文件「五」共四项条款，拆解为 21 条可验证要求，逐条响应如下。其中第 21 条为招标未明确的需求缺口，已单独标出。

#招标要求技术响应结论
1部署于 AI 智能体中台之上作为中台应用运行，复用中台算力调度、模型纳管、服务网关与审计体系，不单独建设推理服务满足
2面向门诊、住院、手术、放化疗、随访场景按场景配置文书类型与模板：门诊病历、入院记录、病程记录、手术记录、放化疗记录、随访记录满足

第 21 条不是偏离，是需求本身存在空白，详见下方说明。

必须先厘清的需求缺口：入院记录的主诉与现病史从哪里来

招标「五（一）」列出的数据源是 HIS、LIS、PACS、超声、手术记录——全部是系统记录，没有一项包含问诊内容。而「五（二）」要求生成「入院记录」初稿，入院记录的主诉、现病史、既往史、个人史、家族史，临床上都来自问诊，系统里没有。

三种处理方式，成本与效果差异明显，需院方明确选哪一种：

① 医师结构化录入补充（推荐）——医师在界面上按槽位填写问诊结果，系统负责组织成文。增加少量录入工作量，但完全可控，不引入新的合规问题。

② 引入语音采集——复用模块七（超声语音报告）的院内 ASR 能力，医师口述问诊结果。效果最好，但超出「五」的招标范围，且需另行确认录音合规（伦理与医务处书面意见）。

③ 生成时留空——初稿不含问诊段落，由医师在院内系统内补写。工作量最省，但入院记录初稿的价值大幅缩水，医师大概率会认为「还不如自己写」。

1.2 系统定位与三条底线

底线 01

AI 只到草稿，归档属于医师

系统最高状态为「可复核草稿」，仅回写院内系统草稿区。修订、审核、归档、签名全部由医师在院内系统内完成，系统不触发任何归档动作。

底线 02

数值与固定段落不进模型

生命体征、检验值、剂量、单位走确定性槽位回填；全身体格检查、个人史、婚育史、家族史走结构化勾选。这些内容不经过语言模型。

底线 03

未提及不得改写为「正常」

医师未勾选、系统未取到的内容，一律显示为缺口，不得改写为「未见异常」「否认」「阴性」等否定表述。缺什么就显示缺什么。

边界外声明（永久不做）

不做诊断与治疗建议生成。系统不生成诊断结论、鉴别诊断、用药建议、治疗方案。一旦识别到此类生成意图，停止文书流程而非降级输出。

不做跨患者数据训练。模型永远看不到其他患者的真实病历。院内数据用于模型训练需另行立项、另行授权。

不做自动归档、自动签名、代签。这是产品形态的硬边界，不接受配置项开关。

一期能力边界（可演进，非永久排除）

不做语音采集与转写。招标「五」未要求语音输入，一期输入为「系统数据 + 医师结构化录入」。若院方希望引入语音（见 §1.1 第 21 条方案②），建议复用模块七的院内 ASR 能力，作为独立工作项另行确认，不并入本模块一期范围。

不做病历质控。质控规则库、缺陷闭环管理属招标「六、病历质控智能体应用」范围，本模块仅向质控模块输出结构化数据。

二总体技术架构

架构分八层。核心设计是把「不能容错的内容」和「需要语言组织的内容」彻底分开——前者走模板与槽位，后者才交给模型，两者之间由独立校验层隔离。

接入层
多源数据接入
全部取数经中台统一数据接口，按字段白名单近实时读取。不单独直连业务库，不建立旁路通道。医师结构化录入入口同层接入。
中台统一接口字段白名单按需取数
身份锚定
患者 · 就诊 · 文书类型 三方锁定
三者任一缺失即阻断，禁止进入取数与生成环节。这是防止多患者病历同场的第一道闸，也是整套架构的前置条件。
缺一即阻断session 绑定
事实层
统一事实账本
每条事实含 fact_id、来源类型、证据等级（A/B/C）、确认状态、时间戳、原文切片。冲突保留为 conflict，不由模型抹平。事实账本是后续所有生成动作的唯一输入。
fact_id 可溯源证据分级冲突保留
缺口层
缺口检测与补问
按文书类型必填项清单比对当前事实账本，输出缺口清单。补问每轮 3–7 个中性问题，不提供候选答案，允许回答「不详／未查／待回报」。
必填项比对最多两轮不给候选答案
零模型区
模板引擎 + 确定性槽位回填
生命体征、检验值、剂量、单位走槽位回填；全身体格检查、个人史、婚育史、家族史走结构化勾选。这一段不经过任何语言模型。
模板骨架数值槽位逐项勾选零幻觉
受控生成区
受控语言组织
仅对已确认事实做语言组织，覆盖现病史、专科情况、诊疗经过、出院医嘱等需要时序与语言逻辑的段落。每句映射 fact_id，无法映射的句子不允许产出。
句级溯源不接受新事实数值禁写
校验层
独立校验（上下文隔离）
不带生成过程的对话历史，独立检查：无源陈述、事实冲突、诊断强度升级、左右侧／时间线／单位一致性。生成模块不能自审——自审等于没有校验。
上下文隔离诊断强度检查
交互与回写
医师逐项确认 → 仅写草稿区
医师逐项勾选确认（病史来源、查体、报告、诊断、计划、高风险事件）。存在冲突、关键缺口或未确认项时，禁止回写，走阻断出口。
逐项确认仅写草稿不触发归档
横切能力（贯穿全部层级）

权限管控 · 全操作审计 · 版本快照 · 模板与术语库版本 · 系统监控告警。这五项不归属单一层，但每一层都必须调用，缺失任一项即视为未完成交付。

3.2 事实账本与证据分级

每条输入先标注来源与证据等级，再进入统一事实账本。采集终端不能给事实的等级加分——录音笔、麦克风、录入界面都只是入口，不改变证据等级。

等级来源使用限制
A 级HIS / LIS / PACS 等系统已核实记录可作为冲突判定锚；可作为查体结果、检验结论直接引用
B 级医师录入与医师陈述可承载查体、判断、计划；数值须经确认后进入确定性槽位
C 级患者与家属陈述永不升格为查体结果或诊断；仅用于丰富主诉与现病史

事实条目的字段构成

每条事实包含：fact_id、content、source_type、evidence_level（A/B/C）、fact_status、事件时间、原文切片。

source_type：患者陈述 / 家属陈述 / 医师查体 / 原始报告 / 医师评估 / 已执行操作 / 计划或医嘱 / 待回报结果。

fact_status：确认存在 / 确认不存在 / 未询问 / 不详 / 未检查 / 待回报 / 不适用 / 冲突 / 待医师确认。

无法判定 source_type 时，默认归入最低等级 C 并标记「待医师确认」，禁止升格使用。宁可按低等级处理，不可按高等级使用。

3.3 缺口检测与补问

  • 输入：文书类型必填项清单 + 当前事实账本
  • 输出：每轮 3–7 个中性问题，不提供候选答案——提供候选答案会把问诊变成勾选，诱导医师选「正常」
  • 允许回答「不详 / 未查 / 待回报」，且这些回答本身就是有效答案
  • 最多补问两轮。两轮后仍有关键缺口，停止生成，状态保持「待复核」，禁止进入草稿回写

补问上限是刻意设计的。开放式反复追问会把医师的耐心耗光，结果是医师开始敷衍勾选——那比不补问更危险。

3.4 固定段落与数值的零模型处理

这是本模块最关键的技术判断，也是实测数据支撑最强的一条。

实测基线（来源：85 份真实脱敏住院病历语料）

全身体格检查段落平均 857 字，占整份入院记录的 52%，长度区间仅 837–907 字，68 份样本方差仅 70——几乎逐字相同。这说明它是逐字复制的固定模板，而不是需要语言组织的内容。

这 857 个字不需要文采，需要的是逐项勾选。

最容易出事故的一处

若由模型自动生成「巩膜无黄染、双侧瞳孔等大等圆、心肺腹未见异常」而医师并未实际检查，即为凭空生成查体记录。这类错误读起来完全合理，肉眼极难发现，但属于病历造假范畴。

该段落必须走结构化勾选表单，逐项选择「正常 / 异常描述 / 未查」，禁止默认全部正常。

零模型区覆盖范围

内容处理方式说明
全身体格检查逐项勾选：正常 / 异常描述 / 未查禁止默认全部正常；选「未查」则生成时标缺口
生命体征槽位回填（T / P / R / BP）数值与单位由已确认数据填充
检验值与剂量槽位回填模型输出中不得出现任何数值
个人史 / 婚育史 / 家族史结构化字段记录按字段而非由模型补写

3.5 受控语言生成

这是唯一使用语言模型的环节，约束如下：

  • 输入受限：模型只能看到事实账本中已确认的事实，看不到原始数据全量、看不到其他患者数据、看不到未确认的槽位
  • 输出受限：每个句子必须映射至少一个 fact_id；无法映射的句子不允许产出
  • 数值禁写：模型输出中不得出现任何数值，数值位以槽位占位符呈现，由确定性回填
  • 不新增事实：不得补充事实账本中没有的内容；缺口以「【待补充】」占位呈现
  • 不改写否定：未提及的内容不得改写为「未见异常」「否认」「阴性」
  • 不产出诊断与治疗建议：触发即停止文书流程

受控生成区覆盖的段落

现病史、专科情况、诊疗经过、病程记录叙事段、诊疗小结、出院医嘱、随访记录。

3.6 独立校验

校验类别校验内容
无源陈述报告中是否存在无事实支撑的句子。发现任一即禁止回写
事实冲突同一事实的多次记录是否存在矛盾。冲突保留并提示，不自动抹平
诊断强度升级是否存在把「考虑」写成「确诊」、把「待排」写成「除外」等强度升级
左右侧一致性部位描述与检查记录中的左右侧是否一致
时间线一致性症状起始、就诊、检查、用药的时序是否矛盾
单位一致性检验值单位与参考范围是否匹配
必填项完整性按文书类型校验必填字段
否定表述合规是否存在未提及却写成「无 / 否认 / 正常」的段落

校验模块不携带生成过程的上下文。生成模块不能自审——自审等于没有校验。这是架构级约束，不是配置项。

3.7 医师逐项确认与回写

  • 医师逐项勾选确认，覆盖：病史来源、查体、报告、诊断、计划、高风险事件
  • 无源句子不可勾选；不得用一次性笼统确认替代逐项确认
  • 确认完成后，以「草稿」状态回写院内系统草稿区，非「已签署」
  • 存在冲突、关键缺口未解决、或存在未确认项 → 禁止回写，走阻断出口
  • 系统不触发归档动作；医师在院内系统内的修改、复核、归档责任不可替代

四八条硬约束与六道闸门

以下八条是不可妥协的产品约束，不接受配置项开关；六道闸门是它们的执行机制。

4.1 八条硬约束

数值不经过模型，走确定性槽位回填
模型永远看不到其他患者的真实病历
不自动提交，最高状态只到「可复核草稿」
不产出诊断与治疗建议，触发即停止文书流程
患者陈述永不能升格为查体结果或诊断
模型均本地部署，不调用任何外部接口
未提及不得改写为「无 / 否认 / 正常」
生成与校验必须上下文隔离，不得自审

4.2 六道闸门

身份锚定：患者 · 就诊 · 文书类型

三者任一缺失即阻断，禁止进入取数与生成环节。这是防止多患者病历同场的第一道闸，也是整套架构的前置条件。

未锚定时，取数、生成、录入入口全部拒绝接入。

数值与固定段落不进模型

生命体征、检验值、剂量、单位走槽位回填；全身体格检查、个人史、婚育史、家族史走结构化勾选。模型输出中不得出现任何数值。

数值无处可填时输出「【待补充】」占位，严禁自行填充或推断。

证据等级不可升格

患者陈述永不能升格为查体结果或诊断；无法判定来源类型时默认归入最低等级 C 并标记待确认。

禁止把 C 级事实按 B 级或 A 级使用，禁止升格后作为判定依据。

生成与校验上下文隔离

校验模块不携带生成过程的对话历史，独立判断句子是否有出处。生成模块不能自审。

发现任一无源陈述、冲突或诊断强度升级，禁止回写。

医师逐项确认

逐项勾选确认，覆盖病史来源、查体、报告、诊断、计划、高风险事件。无源句子不可勾选。

不得用一次性笼统确认替代逐项确认；存在未确认项时状态停在「待复核」。

阻断而非降级

存在冲突、关键缺口未解决、或未确认项时，禁止回写，走阻断出口。

阻断是产品能力，不是异常。该拦下来的没拦下来，才是失败。
