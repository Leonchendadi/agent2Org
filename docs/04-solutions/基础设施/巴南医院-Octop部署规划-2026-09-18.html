为什么先澄清再定方案：你给的场景（医院增购昇腾显卡 + 华为服务器，配合原机房联想服务器）恰好是成本最低的一种组合——联想 x86 服务器直接跑官方 amd64 镜像，零改造；昇腾那台只做推理。但里面有一个可能把整个方案推翻的变量：那台华为服务器是裸机还是虚拟机。如果是虚拟化平台且需要把昇腾卡直通给虚拟机，配置复杂度和失败风险都上一个台阶，且部分卡型不支持。这一条没问清之前，下面所有规格都是假设。

一、待甲方澄清清单 先做这一步

下表可直接带去调研会逐条确认。阻塞项（阻塞）不确认则无法定方案；关注项（关注）影响工作量与报价。

1.1 硬件资源

编号问题影响什么级别
H1 华为服务器的具体型号？是 TaiShan 200（鲲鹏 ARM64）还是 2288H V5/V6（Intel x86）？ 决定 Octop 是否需要自建 arm64 镜像（+1–2 人日）。华为既有鲲鹏机也有 x86 机，型号不问清无法判断 阻塞
H2 昇腾卡的型号与数量？Atlas 300I Duo / 300V Pro / 800I A2（910B）？显存多大？ 决定能跑多大的模型、并发多少。也决定是走 MindIE 还是 vLLM-Ascend 阻塞
H3 联想服务器的型号、CPU 核数、内存、可用磁盘空间？ Octop 需要 ≥4C8G（含浏览器自动化建议 8C16G）+ 100GB 磁盘。原机房服务器可能已被其他系统占用 阻塞
H4 是否有共享存储 / NAS / 备份一体机？ 决定数据卷与 PG 备份方案。医院通常有备份一体机，能复用就省事 关注
H5 是否有 UPS、机房是否有独立机柜空间与供电余量？ 昇腾卡功耗高（300W+），机柜供电与散热需确认 关注

1.2 平台与操作系统

编号问题影响什么级别
S1 两台服务器的操作系统与版本？（openEuler 20.03/22.03、麒麟 V10 SP3、统信 UOS、CentOS 7/8、Ubuntu 22.04） 昇腾 HDK 对不同 OS 有对应的包；CentOS 7 内核过旧可能装不了新版 CANN 阻塞
S2 容器引擎是什么？Docker（版本？）/ containerd / iSulad？是否已有 K8s？ openEuler 默认引擎可能是 iSulad，我们的 docker compose 方案不通用，需改造成本 +2–3 人日 阻塞
S3 服务器是裸机还是跑在虚拟化平台上（FusionCompute / VMware / 深信服）？ 本条最关键。见 1.3 阻塞
S4 是否已安装昇腾 HDK / CANN？版本号是多少？谁装的？ CANN 与内核、固件强绑定。已有环境要适配，不能假设可以从零装 阻塞
S5 是否已安装 Ascend Docker Runtime（ascend-docker-runtime）？ 昇腾容器跑起来的前提。没有则需要装 + 重启 dockerd，涉及停机窗口 关注
S6 是否有国产化 / 信创强制要求？招标文件里是否写明"必须运行在国产 CPU 上"？ 决定 Octop 可以跑联想 x86（省 1–2 人日）还是必须迁到鲲鹏。这一条直接改方案 阻塞

1.3 虚拟化与设备直通 高危

编号问题影响什么级别
V1 华为服务器上的昇腾卡是物理直连给操作系统，还是要 PCIe 直通（passthrough）给某台虚拟机？ 若需直通：要在 BIOS 开 IOMMU / ACS，配置 vfio-pci 绑定，部分昇腾卡型对虚拟化直通支持有限甚至不支持。这是能把方案推翻的一条 阻塞
V2 虚拟化平台的 NPU 直通有没有现成的成功案例？能否让华为原厂确认支持？ 如果没做过，建议直接改用裸机部署推理服务，别在虚拟化上冒险 阻塞
V3 联想服务器上是否也要跑在虚拟机里？ Octop 跑虚拟机没问题（普通容器，不需要设备直通），只是性能略降，可接受 关注

1.4 网络与安全合规

编号问题影响什么级别
N1 两台服务器是否同网段互通？中间有没有防火墙策略需要报备开通端口？ Octop 要访问推理服务的 HTTP 端点（通常 8000/1025 端口）。跨网段需走变更审批，可能拖 1–2 周 阻塞
N2 院内网能否访问公网？是否有出口白名单机制？ 影响两件事：① 镜像与依赖如何交付（决定是否需要离线导入，+0.5 人日）；② IM 通道（飞书/钉钉/企业微信）需要公网长连接，内网隔离则IM 集成直接不可用 阻塞
N3 需要哪些 IM 通道？如果内网不能出网，是否接受只用 Web 控制台？ IM 通道是 Octop 的核心卖点之一。若不可用，需求范围与报价都要改，且要提前告知客户，不能到验收才发现 阻塞
N4 等保等级是几级？有没有安全加固基线要求（如禁止 root 运行、要求日志留存 180 天）？ 决定加固工作量（+2–3 人日）。我们的加固包已做非 root 运行、capability 收敛，可复用作整改材料 关注
N5 是否有堡垒机 / 准入系统 / 日志审计平台需要接入？ 接入审计平台通常有额外开发或配置工作量 关注
N6 系统的使用终端是什么？院内 PC 浏览器版本？有没有国产 OS 终端？ Octop 前端是 React SPA，需现代浏览器。若终端是 IE 或老旧国产浏览器，需要额外适配 关注

1.5 模型与推理服务归属

编号问题影响什么级别
M1 要跑哪个模型？DeepSeek-V4-Flash 还是别的？模型权重由谁提供？ 决定显存需求与推理服务选型。权重来源不明则无法估算部署工作量 阻塞
M2 推理服务（MindIE / vLLM-Ascend）的部署是否包含在我们的交付范围？还是华为原厂 / 其他集成商负责？ 直接决定报价。推理服务部署 5–15 人日，且强依赖昇腾生态经验。若不在我们范围内，只需对方提供一个 OpenAI 兼容端点即可 阻塞
M3 模型权重的商用许可由谁负责？医院是否已有采购凭证？ 合规风险。医院场景一旦涉及患者数据，模型许可与数据使用条款要留痕 关注
M4 是否允许调用外部云端大模型 API 作为兜底？ 患者数据出院是红线。若允许，需要脱敏方案与合同条款；若不允许，全部走院内推理 关注

1.6 业务与规模

编号问题影响什么级别
B1 使用人数与并发？峰值时段（早交班？）预计多少人同时用？ 决定服务器规格与推理卡数量。Octop 单副本，需按峰值内存规划 关注
B2 要哪些具体能力？文档处理 / 浏览器自动化 / 定时任务 / 知识库 RAG？ 浏览器自动化需在容器内预装 Chromium，内存需求从 8G 提到 16G 关注
B3 是否需要接 HIS / EMR / LIS 等院内系统？接口由谁提供、走什么协议？ 典型成本地雷。HIS 接口往往需要厂商配合，周期不可控，可能成为整个项目的关键路径。本条必须单独立项评估 关注
B4 数据范围：是否涉及患者隐私数据？是否需要脱敏？ 影响安全设计与等保材料 关注

1.7 运维责任边界

编号问题影响什么级别
O1 昇腾驱动 / CANN / 固件的升级与故障处理由谁负责？ CANN ↔ 内核 ↔ 固件强绑定，内核一升级驱动就得重装。这是长期成本，必须在合同里写清责任方 关注
O2 服务器硬件维保由谁承担？是否在保？ 影响故障响应时间承诺（SLA） 关注
O3 运维期长度（1 年 / 3 年 / 5 年）？响应时限要求？ 影响报价结构。Octop 是 MIT 开源项目、上游 harness-* 依赖未开源，维保能力需要我们自己兜 关注

二、候选拓扑 两个方案

方案 A：异构分离（推荐）

Octop 跑在联想 x86 服务器上（用官方 amd64 镜像，零改造），昇腾华为服务器只做推理服务，两者内网 HTTP 互联。

维度方案 A：异构分离方案 B：全信创同构
Octop 部署位置联想 x86 服务器华为鲲鹏服务器（ARM64）
镜像官方 amd64 直接可用需自建 arm64（+1–2 人日）
容器引擎风险低（x86 上 Docker 生态成熟）中（openEuler 可能是 iSulad，+2–3 人日）
NPU 耦合零零（Octop 仍不碰 NPU）
国产化合规可能不满足强制信创要求满足
适用条件招标文件未强制"必须运行在国产 CPU"招标文件强制国产化，或客户明确要求
建议：默认按方案 A 报价，把方案 B 作为"若甲方强制信创"的增项。理由是方案 A 把 Octop 与昇腾生态彻底解耦——昇腾那侧出任何问题（驱动、CANN、模型适配）都不会阻塞应用层交付，风险敞口最小。但方案 A 成立的前提是 S6 澄清结果：招标文件没有强制国产 CPU。

四、实施步骤 五阶段

阶段内容交付物 / 验收标准前置条件
P0
澄清		 调研会逐条确认 23 项；现场看服务器与机房 澄清清单签字版；确认方案 A / B；确认交付边界（尤其 M2） 当前
P1
环境准备		 服务器系统与容器引擎就绪；开通网络端口；镜像离线导入 docker run hello-world 通过；两机 HTTP 互通；镜像已 load P0 完成
P2

P3

P4
加固与验收		 等保整改项落实；备份策略上线；文档与培训；验收测试 等保整改确认；备份可恢复演练通过；培训记录；验收报告签字 P3 完成

报价前必须锁死的两条边界：
① 推理服务是否在我们范围内（M2）。这 5–15 人日和 Octop 侧的 10–14 人日是两种完全不同的能力，混在一起报价会失真。
② IM 通道是否可用（N2/N3）。如果内网不能出网，Octop 的 IM 集成能力（飞书/钉钉/企微）全部作废，产品价值要重新向客户说明——这不是技术问题，是需求边界问题，必须提前谈。

六、风险地雷 按致命度排序

序风险后果应对
1 虚拟化平台 + 昇腾卡直通（V1） 直通配置失败或卡型不支持，推理服务无法部署，整个项目卡在起点 坚持裸机部署推理服务；若必须虚拟化，要求华为原厂书面确认支持
2 内网不出网导致 IM 通道不可用（N2/N3） Octop 的核心交互入口失效，客户预期落空，验收纠纷 P0 阶段明确告知并写进需求确认书；备选方案为纯 Web 控制台
3 HIS/EMR 接口依赖第三方厂商（B3） 周期不可控，成为关键路径，拖垮整体交付 单独立项、单独报价；合同中明确"接口依赖甲方协调"
4 CANN ↔ 内核 ↔ 固件版本绑定（S4/O1） 一次内核升级就可能导致推理服务不可用，且修复需要原厂介入 合同写清驱动运维责任方；升级前先在测试环境验证
5 Octop 单副本无高可用 容器故障即服务中断，恢复依赖重启 + 数据卷完整 接受该约束并告知客户；配置自动重启 + 定期备份 + 恢复演练
6 上游依赖未开源（harness-*） 深层故障无法定位到源码，只能依赖上游响应，而项目无商业 SLA 维保报价中预留风险系数；优先使用官方镜像与官方路径，减少自研改动
7 网络端口审批周期（N1） 技术就绪但卡在流程，实际工期被拉长 合同签订后立刻发起变更申请，不等部署阶段
