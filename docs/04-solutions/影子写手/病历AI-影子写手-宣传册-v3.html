Why / The real problem
02 / 07

真正危险的，
不是 AI 文笔不好，
而是它会把信息缺口写得很顺。

错别字谁都能看出来。难审的是另一种错误：体征、数值、时间写得临床上完全合理，却没有任何出处。

普通"生成式病历"

  • 把病历和检索片段一起交给模型
  • 缺字段时按常识自动补全
  • 不同患者的相似病例可能同场出现
  • 生成后难以回答：这句话从哪里来？

影子写手

  • 先锁定患者、就诊、文书类型
  • 先建事实账本，再组织语言
  • 缺口显示为缺口，不改写为"正常"
  • 患者特异性句子逐句映射事实 ID

How / Three sources
03 / 07

三类输入，
先分等级，再进账本。

每条输入先标注来源与证据等级，再进入统一事实账本。录音笔和麦克风只是采集终端，不能给事实的等级加分。

A · 系统锚点

HIS / EMR 已核实事实

当前患者、当前就诊、当前文书所需字段按白名单近实时读取。检验、医嘱、护理生命体征、已签发报告均需带状态。

只有 verified 数据可作为冲突判定锚
B · 医生陈述

医生单人口述

由录音笔、领夹麦或工作站麦克风采集，院内 ASR 转写。它可以承载查体、判断、计划，但必须保留语义标签。

数值先确认，再进入确定性槽位
C · 患方陈述

医患对话

患者与家属陈述可丰富主诉与现病史，也可暴露事实冲突；但它始终只是患者或家属的陈述。

永不升格为查体结果或诊断
统一事实账本，而非把所有内容塞进提示词

每条事实包含 fact_id、source_type、fact_status、事件时间与原文切片；冲突保留为 conflict，不由模型悄悄"抹平"。

影像边界：PACS 图像仅作展示引用；进入事实账本的是放射科已签发报告，不让模型读片下诊断。接口字段、时延与权限以院方正式授权为准。

A 级做判定锚，B 级承载叙事，C 级永远只是陈述证据等级，决定每条事实能用在哪里
How / Right engine, right job
04 / 07

不是所有病历文字，
都应该经过大模型。

实测 68 份断指再植入院记录：全身体格检查平均 857 字，占整份 52%，长度区间只有 837 到 907 字，几乎逐字相同。这 857 个字不需要文采，需要的是逐项勾选。

产品原则

把模型放在它擅长的地方

模型负责整理已确认事实、形成医生可读的叙事；规则、模板与槽位负责不能容错的内容。幻觉源消除了，高价值的语言组织才真正留给 AI。

ZERO MODEL ZONE

结构化事实 + 模板引擎

全身体检、个人史、婚育史、家族史等内容，按字段记录而非由模型"补写"。

  • 逐项选择：正常 / 异常描述 / 未查
  • 禁止默认"全部正常"
  • 模板填充，不产生语言模型幻觉
CONTROLLED LLM ZONE

事实账本 + 受控组织生成

现病史、专科情况、诊疗经过、出院医嘱等需要时序与语言组织的部分，才使用 LLM。

  • 每句患者特异陈述映射事实 ID
  • 缺口、冲突、待回报显示在正文之外
  • 生成后进入独立校验 agent
生命体征、检验值、剂量、单位不经过模型，全部由已确认数据槽位回填。

How / Safety workflow
05 / 07

一份草稿进入 HIS 前，
必须通过四道不能绕过的关。

01

身份锚定

先锁定患者、就诊、文书类型。未锚定，HIS 取数、语音、图像均拒绝接入。

02

事实与缺口

先按字段白名单取 HIS，再采集口述与对话。系统只问当前缺什么，最多补问两轮。

03

生成与校验隔离

生成 agent 只写有事实支持的正文；校验 agent 不带生成对话历史，独立检查出处、时序、左右侧、数值与诊断强度。

04

医生确认与草稿回写

医生逐项确认后，仅回写 HIS 草稿区。正式修改、复核、签署始终在 HIS 内完成。

Path / From proof to platform
07 / 07

先在一件最难的事上做深，
再把能力带到全院。

PHASE 1 · 专病验证

断指再植影子写手

用三源事实、事实账本、语音与草稿回写跑通一个高风险高复杂度专病。目标是证明：事实可溯、缺口可见、医生愿意用。

PHASE 2 · 科室复制

手外 / 骨科高频文书

将证据规则、字段映射、零模型模板与校验逻辑复制到病程、查房、交接、出院等更高频文书。

PHASE 3 · 医院能力

全院病历生产与质控

面向多科室日常文书与批量质控建设院内 AI 资源池。专病积累的规则与审计能力成为全院底座。

试点启动，需要院方共同确认三件事

1. 当前患者、当前就诊、当前文书的 HIS 字段白名单与草稿区回写边界； 2. 医患录音知情与院内 ASR 部署边界； 3. 一条病区路径、一类文书、一个可冻结的试点基线。
