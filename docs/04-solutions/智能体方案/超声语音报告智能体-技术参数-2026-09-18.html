一模块定位与需求溯源

本模块解决一件事：超声科医生在检查过程中口述，系统实时生成一份结构化、可复核、可溯源的报告草稿，医生确认后回写院内系统。系统不做诊断，不读图像，不自动签发。

1.1 招标条款响应总览

招标文件「七」共三项条款，拆解为 22 条可验证要求，逐条响应如下。偏离项已显式标注，不做隐性回避。

#招标要求技术响应结论
1支持医用麦克风语音采集支持 USB 医用麦克风、3.5mm 领夹麦、网络麦三种接入；采样 16kHz/16bit 单通道，可扩双通道。设备型号由现场勘察后与科室共同确定（见 §10）满足

「条件满足」指技术上具备能力，但最终实现程度取决于院内既有系统的开放程度，已在 §10 列为阻塞待确认项。

关于第 22 条的偏离说明（需当面确认口径）

招标「七（一）」表述为「医生口述检查内容即可实时生成结构化报告」，严格读法可理解为流式实时出稿；而「七（三）」表述为「口述完成后输出报告」。本方案以「七（三）」为依据，一期按检查结束后一次性生成交付。

这一条的读法差异会直接影响工作量与技术风险，建议技术交流时当面确认。若甲方坚持流式口径，需重新评估工期与算力配置——实时流式对降噪、增量识别、低延迟推理的要求显著更高，且在多机同室环境下更难保证声源归属准确。

1.2 系统定位与三条底线

底线 01

不替代医师诊断

系统只做语音到结构化文本的转换与规范表述。不输出诊断意见、不做鉴别诊断、不推荐分级。分级由医生口述，系统只做白名单校验与一致性告警。

底线 02

数值不经过语言模型

测值、单位、分级、部位全部走确定性槽位回填。语言模型只负责把已确认事实组织成医生可读的句子，不接触、不生成任何数值。

底线 03

AI 只到草稿，签名属于医生

系统最高状态为「可复核草稿」，仅回写院内系统的草稿区。报告的审核、修改、签发在院内系统内由医生完成，系统不代签。

明确的边界外声明（本项目不做）

不做超声图像 AI 识别。本模块不读取超声图像做病灶检出、自动测量或良恶性判断。这类功能属于医疗器械监管范畴（通常需 NMPA 二类／三类证），与招标文件「七」的要求范围不一致，本项目不包含。

不做诊断性结论生成。系统不生成「考虑……可能」「建议……检查」类诊断推理文字，除非该表述由医生口述且经医生确认。

一期能力边界（可演进，非永久排除）

不做实时流式（边扫边出稿）。一期采用检查结束后一次性生成。依据是招标「七（三）口述完成后输出报告」；但「七（一）实时生成」的严格读法可能被理解为流式，详见 §1.1 第 22 条偏离说明。建议技术交流时当面确认口径。流式列为二期演进项。

不做说话人分离。一期不区分医生语音与患者／他人语音。因此多机同室的声源隔离只能依靠硬件与工位绑定，不能依靠算法，见 §3.3.1。这也意味着 A6 的现场勘察结论对方案成立与否更为关键。

二总体技术架构

架构分七层，核心设计是把「不能容错的内容」和「需要语言组织的内容」彻底分开：前者走模板与槽位，后者才交给模型。两者之间由校验层隔离。

采集层
音频采集与声学前端
医用麦克风／领夹麦拾音 → 本地声学前端（降噪、去回声、自动增益）→ 16kHz 单声道音频流。脚踏开关与热键信号同层接入。
16kHz / 16bit稳态噪声抑制本地处理
识别层
院内语音识别（ASR）
本地部署中文医疗 ASR，挂载超声术语热词表（解剖部位、分级词汇、常用描述）。一期采用整段批处理：检查全程录音，结束后统一转写，输出转写文本 + 时间戳 + 逐片段置信度。音频全程不出院。
院内本地推理医疗热词表整段批处理逐片段置信度
解析层
语义分离与槽位抽取
判别报告内容／非报告内容；从报告内容中抽取部位、测值、分级、描述四类槽位；所有抽取结果进入「待确认池」，不直接生效。
内容判别槽位抽取待确认池
事实层
本次超声事实账本
每条事实含 fact_id、来源类型、确认状态、时间戳、原始口述切片。冲突保留为 conflict，不由模型抹平。事实账本是后续所有生成动作的唯一输入。
fact_id 可溯源来源分级冲突保留
零模型区
模板引擎 + 确定性槽位回填
报告骨架、必填项、测值、单位、分级枚举、左右侧标记，全部由模板与槽位确定性填充。这一段不经过任何语言模型。
模板骨架测值槽位枚举白名单零幻觉
受控生成区
受控语言组织
只对已确认事实做语言组织，把口语转为规范医学表述。每句映射事实 ID，无法映射的句子不允许产出。
句级溯源不接受新事实
校验层
独立校验 + 医生确认 + 草稿回写
校验模块不带生成过程的上下文，独立检查无源陈述、左右侧／部位一致性、单位与量级、分级与描述匹配。医生逐项确认后，仅回写院内系统草稿区。
上下文隔离缺一不可仅写草稿
横切能力（贯穿全部层级）

权限管控 · 全操作审计 · 版本快照 · 原始音频留存 · 系统监控告警。这五项不归属单一层，但每一层都必须调用，缺失任一项即视为未完成交付。

参数项技术指标说明

关于识别率的诚实说明

识别准确率高度依赖诊室声学环境、医生语速与口音、以及检查部位术语密度。本文件标注的 CER ≤ 5% 是设计目标，不是承诺值。建议在试点期用科室真实录音做一轮标定，把实测值写进验收口径——这样对双方都更公平。

3.3 报告内容与非报告内容分离

超声检查过程中，麦克风会同时收到报告口述、操作指令、医患对话、教学讲解、环境杂音。系统按以下规则处理：

  • 报告内容：进入槽位抽取与事实账本
  • 操作指令：如「另起一段」「把刚才那句删掉」「报告读一遍」，直接执行，不入正文
  • 医患对话：仅留存音频与转写，不进入报告正文；可用于事后复核
  • 教学讲解：与报告无关的讲解内容不入正文
  • 环境杂音：标记并丢弃，不入正文
  • 同室其他医生的口述：见 3.3.1，此类内容不能靠语义判别处理

判别准确率设计目标 ≥ 95%。判别结果在界面上以不同颜色区分，医生可随时手动改判——任何自动判别都必须可被人工推翻。

3.3.1 同室多机场景的声源串扰（高风险项）

若一个诊室内有多台超声同时检查、同时出报告，每台设备旁的麦克风都会收到邻位医生的口述。这是本模块最危险的一类失效路径，原因是：

为什么语义判别在这里失效

邻位医生口述的内容，在语义上就是一份完整、规范、临床上完全合理的超声报告。它既不是指令，也不是闲聊，更不是杂音——用任何语义分类器都无法把它与本工位的报告内容区分开。

后果是甲患者的报告里出现乙患者的所见与测值。这不是「串抄」，是实打实的串患者，比文本层的跨患者污染更隐蔽——因为内容本身没有语法错误，医生通读报告时很难察觉。

因此，此类风险必须在声学层解决，不能留给语义层。按可靠性从高到低：

  1. 近场定向拾音：领夹麦或喉振麦，拾音距离 ≤ 30 cm，配合增益门限。最可靠，成本也最低
  2. 采集窗口控制：脚踏开关或按键控制采集起止，仅在按下期间收音。确定性最高，不依赖算法
  3. 工位三方绑定：麦克风 ID ↔ 超声设备 ID ↔ 报告会话 ID 唯一绑定；音频无法绑定工位则不进入报告流程
  4. 声纹校验：列入二期。一期不提供说话人分离，此项不可用
  5. 麦克风阵列波束成形：仅作辅助。两人同时说话时分离能力有限，不可作为唯一手段
  6. 物理隔断与吸声处理：最彻底，但属基建改造范畴，成本与工期需单列
对方案与报价的直接影响

若科室确为「一室多机同时检查」布局，则：① 吊装麦／全向麦方案作废，须改用近场定向拾音；② 需增加现场声学勘察与调优工作量；③ 识别率指标的前提条件发生变化，须按多声源环境重新标定；④ 一期不提供说话人分离，算法侧没有兜底，声源隔离完全依赖硬件选型与工位绑定，容错空间更小。此项已列为 §10 阻塞项 A6。

分级体系BI-RADS／TI-RADS／LI-RADS／O-RADS按检查部位自动挂载对应分级体系
分级取值枚举白名单，仅接受白名单取值模型不允许生成白名单外的新分级
一致性校验分级与所见描述匹配性检查如描述「形态规则、边界清晰」却输出 BI-RADS 5，触发告警

3.6 口语到规范医学表述（受控生成）

这是唯一使用语言模型的环节，约束如下：

  • 输入受限：模型只能看到事实账本中已确认的事实，看不到音频、看不到其他患者数据、看不到未确认的槽位
  • 输出受限：每个句子必须映射至少一个 fact_id；无法映射的句子不允许产出
  • 数值禁写：模型输出中不得出现任何数值，数值位以槽位占位符呈现，由确定性回填
  • 不新增事实：模型不得补充事实账本中没有的内容；缺口以「【待补充】」占位呈现
  • 不改写否定：口述未提及的内容不得改写为「未见异常」「阴性」等否定表述

3.7 截图绑定

  • 从超声工作站按检查序号抓取静态图，与报告条目绑定
  • 支持 DICOM 图像与位图两种来源，具体取决于工作站能力（见 §10 阻塞项 B1）
  • 图像仅作展示引用，不进入推理链——系统不读图、不测量、不下结论
  • 图像存储于院内，与报告版本关联，随报告一同回溯

四六道安全闸门

超声报告的风险不在文笔，而在四处：测值错、左右侧错、分级错、串患者。前三类写出来临床上完全合理、肉眼很难发现，后果直接；第四类更隐蔽，内容本身毫无破绽，只是不属于这个患者。以下六道闸门专门针对这四类风险。

音频必须绑定到确定工位

每路音频必须唯一绑定「麦克风 → 超声设备 → 报告会话」三方。同室多机场景下，邻位医生的口述在语义上就是一份完整报告内容，靠语义分类无法剔除，只能靠声学来源隔离。一期不提供说话人分离，算法侧没有兜底，这道闸门只能靠硬件与绑定实现。

音频无法绑定到确定工位时，拒绝进入报告流程。不允许「先收进来，再猜是谁说的」。

数值不进模型

转写中抽出的所有数值一律进「待确认池」，经医生确认后由确定性槽位回填。语言模型在任何环节都不接触、不生成数值。

若某数值无处可填，输出「【待补充】」占位，严禁自行填充或推断。

左右侧与部位一致性

检查部位标记、患者既往记录、描述文本中的左右侧标记三方交叉校验。超声场景中左右侧写反是最高频的严重缺陷。

三方不一致即阻断，必须医生显式裁决后方可继续。

分级走枚举白名单

BI-RADS 等分级只接受白名单取值，模型不允许生成白名单外的新分级。分级与所见描述做匹配性校验。

分级与描述矛盾时告警并阻断提交，不自动修正为「更合理」的取值。

生成与校验上下文隔离

校验模块不携带生成过程的对话历史，独立判断句子是否有出处。生成模块不能自审——自审等于没有校验。

发现任一无源陈述或未解决冲突，禁止回写。

医生逐项确认

槽位与句子逐项确认，无源句子不可勾选。不得用一次性笼统确认替代逐项确认。

存在未确认项时，报告状态停在「待复核」，无法进入草稿回写。

设计取向：阻断是产品能力，不是异常

很多同类产品把「顺利生成」当成功指标。我们的判断相反：该拦下来的没拦下来，才是失败。系统宁可多停一次让医生确认，也不放过一个无源句子进报告。

与「病历生成智能体」的关系

两者共用同一套底层设计（事实账本、来源分级、槽位回填、生成校验隔离、逐句确认），差异在输入形态：超声模块以实时语音为主输入，病历生成以多源业务数据聚合为主输入。底层引擎与安全机制可复用，模板库与槽位定义各自独立——这是分期建设中成本可控的关键。
