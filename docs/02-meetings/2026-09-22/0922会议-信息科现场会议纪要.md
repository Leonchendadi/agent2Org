## <a id="_Toc_section_2"></a><a id="section-2"></a>一、一句话结论

__这次会是"利好 \+ 冲突"同时出现。__利好：所有系统都已接入 ESB 集成平台，接口不用逐个对接，0920 会上的最大技术风险大幅下降。冲突：主任的真实诉求是__全院级内涵质控__，且信息科的规划里__前 80–90 万就是做全院的__——这与我们"只做宫颈癌专病"的收口策略正面相撞。主任自己也给了台阶：__做浅一点，先看到效果__，并且__中秋节前要初步方案__。

## <a id="_Toc_section_3"></a><a id="section-3"></a>二、逐议题结论

本场会共讨论 15 个议题，以下按会议实际顺序整理，每条末尾给出结论或待办。

### （一）内涵质控——这是主任真正的痛点（本场会的主线）

- 主任原话："主要是针对内涵质控……以前已经上了（系统），但以前没有内涵（质控）。"
- __现有质控的三大问题__：①事后（临床已发生，医务科再抽查）；②效率低、要投很多人；③覆盖面窄（只能抽查，抽不到就漏）。
- __诉求：用 AI 智能体做到"事中"实时质控__，不一定建应用系统，智能体更好。
- __强控设想__：分级——可放行的放行，强制要求的直接卡掉、__不改好不准提交__；但__允许保存__（否则医生会很恼火）。主任判断"可以避免掉 80% 的事后处理"。
- __生成与质控是一体的__：按质控规则生成，本身就规避大量质控问题。

__注意  ·  范围冲突__

  陈小军提醒"咱们这次只在妇产科、针对宫颈癌"。主任答"__我们那块其实想推全员__"（全员的生成和质控 \+ 反写）。主任给的折中路径：__宫颈癌病历 → 整个妇科 → 全院__，分阶段推。 

  但主任明确："__我们设计的开头八九十万都是做全院的。__"__这是本次会议最关键的信息——信息科的规划口径与我们的收口策略不一致，必须在方案里正面处理。__

### （二）反写接口——从"死穴"降级为"可谈，但要定边界"

- 主任设想的业务流：__智能体生成 → 医生审核 → 个人签名 → 保存提交__。强调"生成好了医生必须审一遍，这个跟原则是相悖的（不能不管）"。
- __最简路径（陈焕提，主任认可）__：__只写草稿层，不落库__；医生审核完、保存时才落"未定"库。对卫宁改造难度最小。
- __待定的边界__：草稿接口要开到什么程度？__带不带图片上传__（口腔科这类科室要带图）？
- 主任态度：反写这块可以让卫宁做改造，"把我们的自动生成的病历嵌到电子病历书写页面里"。
- 陈焕："__这个也是这个项目最大的风险之一。__"

### （三）医生签名与认证

- 主任：认证这块__暂时不做__，"短时间内都不会往外面做，因为那是个双刃剑"。
- 现状：__只做了患者签，没做医生签__。医生签咨询过法务——对内场景，个人生成图片即可，医院认就行（调图片）。理由是病历属于内部文件。
- 谢总补了一句实操风险：出问题时"后台开始去处理"（原话，指纠纷处理），说明这个口子有隐患。

### （四）体检 \+ 随访闭环——主任给了非常具体的业务设计

__主任明确：随访和体检放一起，只做体检的随访。__完整链路如下：

1. 体检结果出来 → 智能体后台自动识别、__分级__（最紧急／可缓）
2. 紧急项__立即通知患者__（短信／公众号／互联网医院推送）——"相当于有点像危急值推送"
3. 第二级：请患者来随访／就诊，__推医生信息 \+ 挂号信息 \+ 挂号支付按钮__
4. 患者线上支付 → 推就诊时间 → 到院直接做检查
5. 数据归到门诊 → __提升体检转化率和收入__

- 主任判断：__只针对体检，不针对全院__。"学院（住院）他们现在有一套基本的随访在用"，我们只切体检这一块。
- __不重复建随访系统__：智能体独立建，取随访系统的数据做推荐应用场景即可。主任原话："随访还是随访的，你取随访的数据来形成智能体……弄一个推荐应用场景就可以了"。
- __风险提示（谢总）__：随访推得太频繁会被投诉（他举了做 25 年随访被病人骂的例子），提醒"退路三天的话别人就烦了"。
- __切入病种__：宫颈癌体检项目主要是 __HPV__。主任："就把赵总请过来，问他针对宫颈癌开展哪些体检项目，取出来做单独提醒。"
- __关键人__：体检主任姓__赵__（领导刚换过，"对这块很感兴趣，你们可以去跟他谈"）；互联网医院现在也是__赵主任__负责。

### （五）两癌筛查——没有系统，暂时不碰

- 妇产科主任要求对接两癌筛查，但__目前是手写／Excel，没上系统__，归"区中心"管，__不归信息科__。
- 谢总提到国家按人头给钱（去年约 98 元／人／年），但钱不补给医院。

### （六）区域远程影像与病理——智能体嵌进区域平台

- __区域平台是万达做的__（基层医疗机构所有 HIS 和业务系统、区内影像／检验／心电几大中心）。
- 主任设想的流程：下级机构不发片，__直接调医院智能体__ → 智能体出初步报告 → 上级医生审核盖章 → 回写下级 PACS 报告模板。
- 现状：__没有智能体，是传统模式__（电子发上来、人工看、出报告）。
- __数据不落地本地，存在区卫健委云上__。
- 识图 AI：医院__没有__。CT 设备上装了 3 个单机小模型（肺结节方向），__跟系统完全脱离__，医生看着手写报告。
- __宫颈癌影像 AI 确认走不通__（陈焕论证）：CT 只看腹部／泌尿，看不到宫颈；宫颈癌要内窥镜／宫腔镜。__宫腔镜报告偏超声这边，不是放射 PACS__。谢总定调："__还是以病历为主吧。__"主任说他会再跟领导沟通。
- __接口协调对象__：卫宁那块医院可协调；__万达那块要通过区卫健委__（谢总说"区卫健委也能解决"）。

### （七）集成平台与 ESB——重大利好

- 主任：__所有系统都进了 ESB 集成平台__，"接口是复用的""__不需要逐个去对接__""哪里还有那么原始的方式"。
- 陈小军确认："都是集成平台了是吧？"主任："都是集成平台上面。"
- __影响__：0920 会上最担心的"12 个接口逐个谈、逐个被拿捏"的风险__大幅下降__。取数基本可复用 ESB 接口。

### （九）驾驶舱与 BI——主任主动降级

- 主任："__驾驶舱这块这次可以先放一放__"，因为涉及病理设备信息对接，医院没有全生命周期设备管理系统。
- 降级后的做法：__先做 PC 端简单 BI 看板__，甚至"一天更新一次"的静态看板都可以；__不做大屏／拼接屏适配、不做移动端__（深色背景、颜色、拼接屏适配都不一样）。
- 主任补一句："其实前期也可以做一个简单一点的，也叫驾驶舱，只是没那么动态的提醒。"

### （十）信创与服务器资源——需要澄清

- 医院__马上要买新服务器__。陈焕问是国产信创 CPU 还是英特尔，转写显示主任确认是__英特尔__。
- 容量：主任说"__容量你不用担心__""__给你供个一两百 T 没问题__"，条件是__不要存大量影像数据__（陈焕也确认只存文字 \+ 少量图片）。
- 容器编排：医院__还没做规划__。陈焕建议__先上简单 Docker，不上 K8S__；只要给 __Linux 系统__，我们自己做容器化。主任同意（"有现成的集群""直接克隆过来"）。
- __华为__：主任提到"跟华为约一下，__他那边也有一个人在跟进这个项目__"，可在中台、算力、资源调配配置上一起沟通。
- 采购节奏：__政府采购，11–12 月才可能到位，起码 3 个月起步__。主任："英伟达如果不准采，基本上都是华为的。"

__注意  ·  需书面确认__

  0920 内部会判断"政府项目禁用英伟达、只能华为鲲鹏\+昇腾"，但这里提到的是"新购的这台华为的相关东西 \+ 英特尔 CPU 服务器"。 

  要问清：__华为的部分具体是什么（昇腾算力卡？）、英特尔服务器是否合规、信创要求到底覆盖哪些层面。__

### （十一）中台范围——主任只要"基本管理功能"

- 主任原话："__中台那个事情，中台去敲一下，基本管理功能我们第一期把它做出来就行了__。比如算力的池化、模型的纳管，这几个稍微重要一点的，先纳入到一期里面来。"
- __这一条直接呼应 0920 会的核心矛盾__：主任并不要求把招标文件里那套"统一技术底座"全量交付，只要基础管理能力。__这是可以谈的口子。__

### （十二）数据要素与科研立项

- 若要构建__高质量数据集__并后期__上市交易／挂牌__，必须走__科技成果转化通道__，需院内__科研立项__。
- 只做院内科研分析 → 不用立项；要上市挂牌 → 必须立项，否则医院无法获得收益。
- __伦理与知情同意__：只用__院内历史病历数据__ → 可走__免知情同意__（伦理审查时）；__现场筛查收集患者数据__ → 必须有__患者知情同意书__（可电子版，但必须有）。
- 数据要__滚动更新__就必须从一期就做知情同意，否则后期补不上。主任听懂了："有点像 GCP 做药品，受试者进来要签一套东西。"
- 主任判断"这个是小事"（医院 GCP 做得风风火火），归口__科教科__。谢总：__下午问大数据主任__（当天下午有大数据局的会）。

### （十三）准入合规——主任主动提的，且是真风险

- 主任原话："医院那边一般是走采购……__你们能够提前来做的话，也是违反采购一些规则的__。"
- 主任列的风险：__会引起其他厂商质疑投诉__；__政府不发文__；"__最近审计查得很严__"。
- 主任主动给了模式参考：__三峡医院跟华为__——"__先走的那种，让华为进来做，医院跟厂家一起合作搞人工智能，出了成效过后才走的采购__"，偏__科研共建合作__。
- 谢总回应：已向区里汇报过一次（项目就在产业园旁边），"__同等条件下肯定会优选我们__"，合规进入方式他再落实、再给院长对接。

### （十四）交付节奏——主任明确要"做浅"

- __主任要求：中秋节前给初步方案__（"国庆之前还有三天"）。
- 主任原话（很重要）："__做浅一点，其实医院你一来就上那么多，第一你建设周期也长，第二建好了不一定能够用。做浅一点更好，效率更高，临床马上能看到效果，有利于第二期的推动。你搞深了，前面时间上不去，上去了大半也用不起，反而影响后期建设。__"
- 抓手：__以临床老师的体验和应用需求、以及患者体验为主__。

### （十五）沟通渠道

- 谢总想拉群但没找到（主任"可能有 200 个群，每天每个群的问题平均处理 2 分钟，400 分钟就过去了"）。
- 结论：__先单向联系__，方案出来后再考虑建群；或面对面建群。信息先汇总到主任这边。

## <a id="_Toc_section_5"></a><a id="section-5"></a>四、待确认问题清单（更新版）

以下 12 项需在与院方、平台公司、厂商的后续沟通中逐条确认。

1. __内涵质控范围__：一期是"宫颈癌 → 妇科"，还是主任说的"开头 80–90 万就做全院"？两者差一个量级，必须书面确认。
2. __服务器与信创__：新购服务器 CPU 是英特尔还是国产？华为那部分具体是什么（昇腾卡／鲲鹏）？信创要求覆盖哪些层面？是否影响我们部署方案？
3. __草稿接口规格__：卫宁是否提供草稿接口？__是否支持图片上传__？落库时机（保存时落未定库）是否可行？
4. __ESB 接口清单__：现有 ESB 上已有哪些接口可复用？取数与回写分别覆盖到什么程度？
5. __万达区域平台接口__：走区卫健委协调，具体接口方与周期？
6. __驾驶舱降级确认__：确认只做 PC 端 BI 看板、不做大屏／移动端、不做病理设备对接。
7. __体检系统与公众号__：体检（卫宁）\+ 公众号（金蝶）\+ 互联网医院，三方对接边界与责任方。
8. __随访数据取数__：现有随访系统是哪家？取数接口是否在 ESB 上？
9. __数据集合规__：一期只用历史病历数据（免知情同意）还是从现场筛查开始（需知情同意）？是否走科研立项？
10. __准入合规路径__：能否参照三峡—华为的"先合作出成效再采购"模式？由谁出文？
11. __中台范围确认__：主任说的"基本管理功能"具体清单（算力池化、模型纳管等），是否可作为一期交付边界？
12. __两癌筛查__：确认不在本次范围（无系统、不归信息科）。
