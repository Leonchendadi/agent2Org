断指再植专病试点 · HIS 旁路部署 · 院内私有化

状态：头脑风暴版，含待核实假设 部署：院内私有化，不出院区 文书最高状态：copy_ready，签署在 HIS 内完成 接口与伦理为预设置信，需客户书面确认

一、链路逐环节接口约定与失败处理

环节接口约定失败处理
① 身份锚定 输入：医生在应用内选定 patient_id + encounter_id + document_type
输出：session_id，后续所有取数、生成、回写均绑定此 ID		 三者任一缺失 → 阻断，禁止进入取数与采集环节。这是防止多患者病历同场的第一道闸
② HIS 接口取数 协议：院内只读接口，HTTPS + 院方网关鉴权
输入：patient_id、encounter_id、字段白名单（按需，禁止批量同步）
输出：JSON 字段集，每条附 status: preliminary | verified 与采集时间		 超时 → 重试 1 次；仍失败 → 降级为手工粘贴模式，该来源事实标 unverified，且不得作为 conflict 判定锚
③ 语音采集 + ASR 输入：音频（wav/mp3），设备占位（录音笔 / 领夹麦，选型待定）
处理：院内部署 ASR，音频不出院区；场景1 需说话人分离
输出：转写文本 + 时间戳 + 说话人标签
存证：原始音频与转写文本、时间戳一并留存		 ASR 不可用 → 阻断语音链路，改文本输入；片段置信度低于阈值 → 标红待人工确认。
硬规则：转写中抽出的数值一律进"待确认"池，不直接进槽位
④ 图像采集 输入：伤口照片 / 检查报告图片
处理：仅建立与患者的关联；影像本体不进推理链
输出：图像引用 + 医生或报告提供的文字描述		 无法关联患者 → 拒绝入库。
边界：禁止由模型读影像并产出诊断性描述
⑤ 三源归一 → 事实账本 输出：fact[]，每条含 fact_id、content、source_type、evidence_level(A/B/C)、fact_status、原文切片、时间戳
source_type：patient_statement / family_statement / physician_exam / original_report / physician_assessment / performed_action / plan_or_order / pending_result
fact_status：confirmed_present / confirmed_absent / not_asked / unknown / not_examined / pending_report / not_applicable / conflict / awaiting_physician_confirmation
证据等级：A=HIS 系统记录，B=医师陈述，C=患者陈述		 无法判定 source_type → 默认最低等级 C 并标 awaiting_physician_confirmation，禁止升格使用
⑥ 缺口检测与补问 输入：文书类型必填项清单 + 当前 fact[]
输出：每轮 3–7 个中性问题，不提供候选答案，允许回答"不详 / 未查 / 待回报"		 最多两轮。两轮后仍有关键缺口 → 停止生成，状态保持 needs_review，禁止 copy_ready
⑦ 生成 agent 输入：达标 fact[] + 文书模板 + 规范上下文
输出：草稿正文，每句映射 fact_id；生命体征、检验值、剂量走槽位回填，不经模型生成		 任一数值无处可填 → 输出 [待补充] 占位，严禁自行填充
⑧ 校验 agent 输入：草稿正文 + fact[]；不含生成过程的对话历史（上下文隔离）
输出：校验报告——无源陈述、conflict、诊断强度升级、左右侧/时间线/单位一致性		 发现任一无源陈述或 conflict → 回退至 ⑨，禁止回写
⑨ 医生逐句确认 输入：草稿 + 校验报告
输出：逐句勾选确认记录（含病史来源、查体、报告、诊断、计划、高风险事件）		 无源句子不可勾选；不得用一次性笼统确认替代逐项；存在未确认项 → 状态保持 needs_review
⑩ 回写 / 阻断 协议：院方可写接口，仅写草稿区
输出：草稿文本 + 状态标记 draft（非 signed）
审计：取数、生成、回写全链路留痕，保存周期按院方要求		 存在 conflict、缺口未解决、或未逐句确认 → 禁止回写，走阻断出口

二、不可妥协的硬约束

  1. 数值不经过模型，走槽位回填
  2. 模型永远看不到其他患者的真实病历
  3. 不自动提交 HIS，最高状态只到 copy_ready
  4. 不产出诊断与治疗建议，触发即停止文书流程
  1. 患者陈述永不能升格为查体结果或诊断
  2. ASR 与 LLM 均本地部署，不调用外部接口
  3. 未提及不得改写为"无 / 否认 / 正常"
  4. 生成与校验必须上下文隔离，不得自审
最容易出事故的一处：全身体格检查占入院记录 52% 篇幅（实测 857 字符，68 份方差仅 70），是逐字复制的固定模板。 若由模型自动生成"巩膜无黄染、双侧瞳孔等大等圆"而医生并未实际检查，即为凭空生成查体记录。 该段落必须走结构化勾选表单，逐项选择 正常 / 异常描述 / 未查，禁止默认全部正常。

三、待客户确认项

事项需要确认的内容
HIS 接口只读 / 可写权限范围；可取数据项（检验、医嘱、护理生命体征、PACS、报告）；实时性；审计字段要求
回写边界草稿区的写入权限与状态标记方式；医生在 HIS 内修改后能否读回（关系到事实账本与正式病历是否一致）
录音合规医患录音的伦理与医务处书面意见；原始音频留存策略与加密要求
ASR 部署院内 GPU 资源归属；方言（白话 / 壮语口音）适配需求；是否需说话人分离
硬件选型录音笔 / 领夹麦；导入式还是实时流式；是否需多通道（场景1 医患分离）
说明：本页为头脑风暴阶段的设计基线，篇幅数据来自 85 份真实脱敏病例实测（calc_corpus_stats.py 可重跑）， 接口与合规条款均为预设，需客户书面确认后方可进入开发。
